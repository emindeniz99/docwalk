## Learnings

- 2026-11-05: reveal.js: `keyboardCondition: "focused"` ignores Tab and programmatic focus (use a DOM-focus function); slides sit at z-index 10-12; it binds Escape and O (rebound to no-ops); it paints `.reveal` backgrounds; scroll view starts at 435 px (`scrollActivationWidth: 0`); distant slides are `display: none` (measure clones); any nested `<section>` becomes a vertical slide (content sections become divs); it lays out only on window resize (panels dispatch one). It marks every slide but the current one `hidden` and `inert` yet leaves it `display: block`, so `checkVisibility()` is true and `focus()` does nothing: test `closest("[inert], [hidden]")` before returning focus to a block. It rounds its scale to 0.01 after `maxScale`; with `margin: 0` the slide overhung the screen by up to 0.5% (1446 px at 1440), and capping `maxScale` at the fit rounded down (set before reveal's own resize listener) keeps it inside; its default `maxScale` of 2 also stops a slide short of screens wider than 2560 CSS px. This build scales `.slides` with a transform, never `zoom`.
- 2026-11-05: Paginate before reveal.js initializes, split on the AST (its Markdown plugin is not fence-aware), and fit diagrams from the SVG viewBox; measure each Mermaid host, not only the slide. Page cuts differ by engine, so an e2e test on a paginated section reads each screen's pages from the DOM. Numbering blocks per page breaks whenever one screen blocks an image the other loaded; only blocks that never split (code, images, diagrams) can be numbered across a section, and tables still count per page. `paginateSlide` takes the last top-level `[data-footnotes]` (an author can put that attribute on a raw `<section>`).
- 2026-11-05: Fullscreen only paints the fullscreen element's subtree: put the page root in fullscreen or portalled dialogs vanish. Firefox and WebKit really enter fullscreen under Playwright and keep Escape for leaving it, so the page never sees the key; App replays Escape into an open dialog on `fullscreenchange`, so the overview or sketch closes and presenting continues windowed.
- 2026-11-05: Integration bugs pass per-module tests and show only in the assembled app; round 1's merge found three (comments lost on workspace files, agent writes skipping the comments edit path, a 16.7 MB precache).
- 2026-11-05: React Aria: `ListBox` with `selectionMode` reports clicks as `onSelectionChange`; collections cache rows per item object (put row data in the items or pass `dependencies`); `GridListItem` takes its name from `textValue`; Tree rows are DOM siblings; Radio, Switch and Checkbox inputs are visually hidden (click the label or card in Playwright); modals portal to `<body>` (block app keys with a document listener, not stopPropagation on the dialog). `Menu` draws its empty state ("No match") inside a `role="menuitem"` wrapper, so a test that counts menu items leaves out the one holding `.docwalk-palette-empty`. `ToastRegion` renders nothing while its queue is empty, so its landmark registers only when its label changes; under `exactOptionalPropertyTypes` its props reject `undefined` (add an optional prop conditionally). `IconButton` replaces its default class when given a `className`: pass `docwalk-icon-button` too.

React 19's `act(() => fn())` returns a thenable, not `fn`'s value.

Browser mode serves real ES modules, so a red test that imports a missing export fails its whole file (the Node unit project fails only that test). A new browser project starts with a cold Vite cache in CI: Vite finds React and React Aria mid-run, reloads, and the next file's iframe never becomes ready (60 s), so list them in that project's `optimizeDeps.include` (`sanitizer-engines` in `vitest.config.ts`). The browser iframe is 414 px wide unless a test calls `page.viewport`. A layout test compares boxes with each other, never a pixel height (CI's fonts drew 18.9 px where the local run drew 21.4 px). Property tests reuse one parsed tree, since re-parsing makes new node objects and identity checks fail for no real reason.

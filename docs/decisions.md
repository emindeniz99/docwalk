# Decision index

Settled 2026-11-05 after a prior-art study and two independent design
reviews. [`prior-art.md`](./prior-art.md) holds the survey, the rejected
alternatives and the evidence behind most rows.

Reversing or narrowing a row needs a later row that names the row it
refines or supersedes, or an ADR in `docs/adr/` when the reasons need more
than a row. Mark the earlier row's status with the row or ADR that replaces
it; never rewrite a row in place.

| 71  | Control seats (refines 68). 10 of a room's 50 sockets are kept for control-key holders, so followers, at most 40, cannot lock the presenter, phone remotes or agents out of a room on reconnect. A control-key holder connects with `?seat=` set to HMAC-SHA-256 of the room id under the control key; the room keeps the SHA-256 of the first token it sees and seats only sockets that match it. The relay stays blind: the token says nothing about either key. The first token is the presenter's or a phone's, because the presenter's tab creates the room id and connects before anyone has a link. The stored hash is deleted once the room is empty, a week after it was set. Rejected: per-address limits (an audience behind one venue address), a role hint without proof (a hostile follower would claim a control seat), a room id derived from the token (room creation in `host.ts` would turn asynchronous). | 73  | State signatures (refines 68). Every follower holds the view key, so any follower could send the others a state, whose `docLink` (a `#doc=` link carries any text) every follower then loads. It signs each state over the room id, its sender id, its counter and the message, inside the ciphertext, so the relay's frame is unchanged. A follower takes nothing under the view key but a state with a valid signature; a follow link without `p=` connects nothing. Remotes and agents trust the control key as before. Rejected: Ed25519 (newer in WebCrypto: Safari 17, Chromium 137). Not covered: another follower can show a late joiner an older signed state until the presenter's next one                                               | accepted                |
| 74  | Seat refusal (refines 71). The join links stay hidden until the presenter's socket has opened once in the room, so an attendee cannot read the room id off a QR code and reach the relay with a made-up seat token first. The relay now refuses a seat token that is not the room's: it accepts the socket and closes it at once with code 4409 (`seat_taken`), before the room-full check, because a refused upgrade reaches browser code only as a bare 1006. Before, such a token got a follower seat. A presenter whose socket is refused this way moves to a new room with a new id, new keys and new links, rather than staying on in a follower seat; this applies on a reconnect too (the stored hash can expire while the room is empty). Phone remotes and agents keep retrying                                                                                                                                                                                | accepted                |

| 75  | Presenting chrome hides when idle. The bar above the slide (counter, address, overview, Exit), the annotation tools and reveal.js's arrows hide after 3 s without pointer, touch or key activity, and reveal.js scales the slide into the freed stage. On a phone in landscape they took a third of the height. A mouse or pen move, a key other than a navigation key (arrows, Page Up/Down, Home, End, Space, B, period), a touch tap on the stage beside the slide, or focus reaching a control brings them back; navigation keys and swipes never do. They stay while a control has keyboard focus, a dialog or menu is open, the mouse rests on the bar, or a stroke is under way. With a drawing tool selected the slide belongs to the tool: taps and moves over it draw and change nothing, and the stage beside it still toggles the chrome. | 77  | Present frame (refines 49 and 75). Presenting has two frames, chosen under More actions › Fill the screen when presenting (on by default, kept in `localStorage`) or from the command palette. **Fill**, the default: reveal.js runs with no margin, the slide drops its corners and shadow, and the app, the stage and the safe-area insets take the slide's colour, so a screen that is not 16:9 shows slide-coloured bars, not dark ones, and a notch sits over slide-coloured padding, never over content. | 76  | Fenced code blocks get language colours (refines 22 and 25). Shiki's tokenizer (`@shikijs/primitive` 4.5.0, the newest release past the 7-day age rule) with its JavaScript regex engine, so no WebAssembly and no CSP change, is one lazy chunk (37 kB gzip) loaded only when a document has a block in one of 24 languages, named as GitHub names them (`ts`, `sh`, `yml`, `py` and other aliases); each grammar is its own chunk, imported from a fixed list, never from a name in the document. Colouring runs on the DOM after both sanitizers: it reads a block's `textContent`, writes it back as text nodes and `<span class="dw-code-…">` elements built with DOM APIs, and keeps the result only if the spans spell the same text. Shiki's CSS-variables theme names each token's colour, and that name is only a key into eight classes (keyword, string, comment, constant, function, parameter, inserted, deleted): no Shiki colour, style or markup reaches the page, and DOMPurify's `style` ban stays. The colours are GitHub's syntax colours as design tokens, the light set on slides and in exports and the dark set in dark document mode, each at 4.5:1 or more on its block. Colour only, never weight or style, so a block's metrics and line breaks do not change. The deck and the presenter's previews colour blocks beside `mermaid.run()` and both finish before the measurement pass; document mode colours beside its diagrams. A grammar that fails to load, or a load that takes over 5 s, leaves its blocks plain for that build; an unknown language stays plain. The highlighter is precached; grammars are cached on first use, so offline a language never opened online stays plain. Cost: the sample deck's first load grows from 912 to 977 kB of decision 43's 1 MB; Shiki's precompiled grammars with its raw engine would save an estimated 18 kB more (measured on a bare bundle, not the app build) but are marked experimental, and `@shikijs/core`'s highlighter instead of the tokenizer costs 6 kB more.

# Decision index

Settled 2026-11-05 after a prior-art study and two independent design
reviews. [`prior-art.md`](./prior-art.md) holds the survey, the rejected
alternatives and the evidence behind most rows.

Reversing or narrowing a row needs a later row that names the row it
refines or supersedes, or an ADR in `docs/adr/` when the reasons need more
than a row. Mark the earlier row's status with the row or ADR that replaces
it; never rewrite a row in place.

## Markdown fidelity (added 2026-11-05)

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Status                                 |

| 60  | Raw HTML is parsed by rehype-raw before rehype-sanitize, so GitHub's schema decides what renders (`details`, `kbd`, `sup`, `img width`); `<style>`, `<svg>` and `<math>` are dropped with their contents, as `<script>` is. Raw HTML that crashes the parser is dropped for that render instead of failing the deck. Alerts run after the sanitizer, so the schema allows no alert classes or SVG                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | accepted; refined by 70                |
| 70  | Raw HTML settles (refines 42, 60). When a document has raw HTML, the sanitized tree is serialized and parsed again until nothing changes. GitHub's schema unwraps elements it does not know (`<marquee>`, `<object>`, `<button>`, `<center>`, `<u>` …), and the parser had kept a `<p>`, `<li>`, `<dd>` or heading open across them, so the unwrapped output nested blocks a browser closes on a re-parse. Stripping those elements was rejected: it drops text GitHub shows. Input that does not settle in three passes renders without its raw HTML. The sanitize-twice property's alphabet includes these elements                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | accepted                               |
| 61  | A slide renders the document's link and footnote definitions with its own section, so a footnote shows on the slide that cites it (numbered per slide, ids prefixed with the section id); document mode keeps GitHub's single list. Content `<section>`s become `<div>`s on slides, because reveal.js reads a nested `<section>` as a vertical slide                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | accepted                               |
| 62  | Headings carry GitHub's `user-content-<anchor>` ids. An address that names no section resolves to the page holding that anchor, so `#some-h4` opens the right page. A heading whose GitHub anchor would be empty (`## 🚀`) gets `heading-<hex code points>` (first 8, numbered on collision): stable under edits elsewhere, unlike a position-based id                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | accepted                               |
| 86  | Task list marks (refines 25, 33 and 60). GitHub shows `- [x]` and `- [ ]` as read-only checkboxes. docwalk removed the `<input>` in both sanitizers, so every task showed as a plain bullet and its state was lost. **The state comes from the Markdown tree, not from HTML.** Right after remark-rehype, each task item's generated checkbox becomes an empty `<span>` carrying `data-docwalk-task="<nonce>:done"` or `":open"`. The nonce is a fresh random value for each `nodesToHtml` call, so a document cannot write a matching attribute. The schema lets that one attribute through on `span`, and `input` is dropped from the schema, so an `<input>`, `<form>` or `<button>` written by the author is removed as before. Once the sanitizer and the settle pass are done, a rehype step after them (like the alerts of decision 25) rewrites each span whose nonce matches into the mark and deletes the attribute from every other element. A forged attribute leaves a plain span with its text. **The mark is a drawing, not a control.** `<span class="docwalk-task-box" data-state="done | open" role="img" aria-label="Task done | Task not done">`, empty, so it adds no text node: slide text search (81), copy and the pagination measure see only the item's words, and nothing in the page is focusable or a form control. The label is in the UI language (`render_task_done`, `render_task_open`). **State is a shape, never colour alone:** an outlined square, with a tick drawn from borders in the done state. Borders print, survive forced colours and need no `url()`, so the HTML export's CSP (`img-src data:`) and a printout without backgrounds still show both states. The outline is `ink-muted` (`slide-muted`on slides) at 3:1 or more on its surface, in both themes and in the export. **No second bullet:**`li.task-list-item`has`list-style: none`and the mark hangs in the gutter where the bullet was, as on GitHub. Marks are inline in the item's text flow, so a list splits between items as before (the mark moves with its item) and the box adds no line height. Every view reads the same string: slides, document view, the presenter's previews and the HTML, PNG and print exports. Rejected: allowing`input`in DOMPurify with`disabled`and`type=checkbox`(an author's`<input>`would pass too, and rule 5 would rest on a filter of attributes), and`role="checkbox"` on the span (it announces a control the page does not have, and needs a name from the item's text). | accepted |

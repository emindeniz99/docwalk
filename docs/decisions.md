# Decision index

Settled 2026-11-05 after a prior-art study and two independent design
reviews. [`prior-art.md`](./prior-art.md) holds the survey, the rejected
alternatives and the evidence behind most rows.

Reversing or narrowing a row needs a later row that names the row it
refines or supersedes, or an ADR in `docs/adr/` when the reasons need more
than a row. Mark the earlier row's status with the row or ADR that replaces
it; never rewrite a row in place.

| 69  | Image gate details (refines 33). A source counts as same-origin only if it stays on the page's origin when resolved against both an https and an http page, so any explicit scheme except `data:` and `blob:` is another host: `https:host/x` is a path on an https page but the absolute `https://host/x` on an http one (`wrangler dev`, `vite preview`, a LAN self-host). | 66  | Workspace details (57, 58): a plain visit reopens the last workspace file (after links, before the draft); OPFS saves 500 ms after an edit; a folder without `FileSystemObserver` is polled every second; zip import keeps `.md`/`.markdown`/`.txt`, drops paths that leave the archive, caps 20 MB packed and unpacked and 2000 entries, writes into a new folder; no writable OPFS (Safari < 26) hides the panel                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | accepted                |
| 67  | Agent messages larger than the relay's 16 KB frame (the document, the slide list, a write) travel as deflated, encrypted parts addressed to one participant; the Worker and its frame cap stay unchanged. Receivers bound open transfers, idle time and inflated size. A write may name the revision (SHA-256 of the text) it edited and is refused if the document changed since. "Allow agent edits" lives only in the presenter tab's memory, so a reload turns it off                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | accepted                |
| 68  | Room keys (refines 8, 59): two random keys per room. The control key (`k=`: phone remote, agents) steers the deck and reads and writes the document; the view key (`v=`: follow link) only gets state and sends a follower's hello. State goes out under both keys, agent answers under the control key only. Each frame seals a random sender id and a counter; a receiver drops a counter it has seen from that sender. Not covered: followers forging slides for each other, replays to a reloaded tab                                                                                                                                                                                                                                                                                                                                                                                                                                                                | refined by 71, 73       |
| 71  | Control seats (refines 68). 10 of a room's 50 sockets are kept for control-key holders, so followers, at most 40, cannot lock the presenter, phone remotes or agents out of a room on reconnect. A control-key holder connects with `?seat=` set to HMAC-SHA-256 of the room id under the control key; the room keeps the SHA-256 of the first token it sees and seats only sockets that match it. The relay stays blind: the token says nothing about either key. The first token is the presenter's or a phone's, because the presenter's tab creates the room id and connects before anyone has a link. The stored hash is deleted once the room is empty, a week after it was set. Rejected: per-address limits (an audience behind one venue address), a role hint without proof (a hostile follower would claim a control seat), a room id derived from the token (room creation in `host.ts` would turn asynchronous). Not covered: a per-socket frame rate limit | accepted; refined by 74 |
| 73  | State signatures (refines 68). Every follower holds the view key, so any follower could send the others a state, whose `docLink` (a `#doc=` link carries any text) every follower then loads. The presenter's tab makes an ECDSA P-256 key pair per room, keeps it with the room in `sessionStorage`, and puts the public key in the follow link (`p=`; the link stays near 190 characters, a version 10 QR code). It signs each state over the room id, its sender id, its counter and the message, inside the ciphertext, so the relay's frame is unchanged. A follower takes nothing under the view key but a state with a valid signature; a follow link without `p=` connects nothing. Remotes and agents trust the control key as before. Rejected: Ed25519 (newer in WebCrypto: Safari 17, Chromium 137). Not covered: another follower can show a late joiner an older signed state until the presenter's next one                                               | accepted                |
| 74  | Seat refusal (refines 71). The join links stay hidden until the presenter's socket has opened once in the room, so an attendee cannot read the room id off a QR code and reach the relay with a made-up seat token first. The relay now refuses a seat token that is not the room's: it accepts the socket and closes it at once with code 4409 (`seat_taken`), before the room-full check, because a refused upgrade reaches browser code only as a bare 1006. Before, such a token got a follower seat. A presenter whose socket is refused this way moves to a new room with a new id, new keys and new links, rather than staying on in a follower seat; this applies on a reconnect too (the stored hash can expire while the room is empty). Phone remotes and agents keep retrying                                                                                                                                                                                | accepted                |

## Markdown fidelity (added 2026-11-05)

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Status                  |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| 60  | Raw HTML is parsed by rehype-raw before rehype-sanitize, so GitHub's schema decides what renders (`details`, `kbd`, `sup`, `img width`); `<style>`, `<svg>` and `<math>` are dropped with their contents, as `<script>` is. Raw HTML that crashes the parser is dropped for that render instead of failing the deck. Alerts run after the sanitizer, so the schema allows no alert classes or SVG                                                                                                                                                                                                                     | accepted; refined by 70 |
| 70  | Raw HTML settles (refines 42, 60). When a document has raw HTML, the sanitized tree is serialized and parsed again until nothing changes. GitHub's schema unwraps elements it does not know (`<marquee>`, `<object>`, `<button>`, `<center>`, `<u>` …), and the parser had kept a `<p>`, `<li>`, `<dd>` or heading open across them, so the unwrapped output nested blocks a browser closes on a re-parse. Stripping those elements was rejected: it drops text GitHub shows. Input that does not settle in three passes renders without its raw HTML. The sanitize-twice property's alphabet includes these elements | accepted                |
| 61  | A slide renders the document's link and footnote definitions with its own section, so a footnote shows on the slide that cites it (numbered per slide, ids prefixed with the section id); document mode keeps GitHub's single list. Content `<section>`s become `<div>`s on slides, because reveal.js reads a nested `<section>` as a vertical slide                                                                                                                                                                                                                                                                  | accepted                |
| 62  | Headings carry GitHub's `user-content-<anchor>` ids. An address that names no section resolves to the page holding that anchor, so `#some-h4` opens the right page. A heading whose GitHub anchor would be empty (`## 🚀`) gets `heading-<hex code points>` (first 8, numbered on collision): stable under edits elsewhere, unlike a position-based id                                                                                                                                                                                                                                                                | accepted                |

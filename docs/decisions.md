# Decision index

Settled 2026-11-05 after a prior-art study and two independent design
reviews. [`prior-art.md`](./prior-art.md) holds the survey, the rejected
alternatives and the evidence behind most rows.

Reversing or narrowing a row needs a later row that names the row it
refines or supersedes, or an ADR in `docs/adr/` when the reasons need more
than a row. Mark the earlier row's status with the row or ADR that replaces
it; never rewrite a row in place.

| 100 | Choosing sections to present (refines 20, 21 and 81). **What it is.** The viewer picks which sections of a long document the deck presents. The others are skipped. The choice is viewer state in the URL (rule 1), spelled with section ids and never with positions (rule 7): `?sections=<id>,<id>`. No parameter means every section. Choosing every section removes the parameter, so a link only carries a real subset. **Format and limits.** Each id is checked like the id in a slide address (the GitHub anchor alphabet, Unicode letters, marks, digits and `_` `-`, at most 200 code points), so a comma cannot occur inside one. Ids are percent-encoded as UTF-8 with `encodeURIComponent` and joined with commas (`%2C`, as for `level`); the tests cover Turkish, CJK and non-BMP ids. At most 100 ids and 4000 characters of encoded value: with `?src=`, `level` and a slide address this keeps a link far below the 8 kB request line that common servers and proxies accept. A repeated id counts once. Parsing is strict: one malformed item (empty, a character outside the alphabet, longer than 200 code points) or a value over either limit makes the whole parameter `null`, as a bad `level` does, and the deck shows every section. Writing a selection over the limits writes nothing; the picker says the link will not carry it, and the selection stays in memory. `#doc=` and `?src=` are never touched, and the parameter works beside both. **Unknown ids.** An id the document does not have is ignored without a message, so a link survives an edit that removed or renamed a section. When none of the chosen ids exist the deck shows every section and the sidebar says so in a status line ("None of the chosen sections are in this document. Showing all N."). The chosen ids stay in memory and in the URL while that lasts, because a heading being retyped passes through ids that do not exist; the next choice replaces them. Opening another document after the page's first one clears the selection, as it clears the address, because ids such as `summary` repeat across documents. **Who obeys.** The deck is built from the chosen sections, so everything that reads the deck obeys with no code of its own: the page counter and the status bar count, the outline, the command palette (titles and slide text search), the slide overview, the address in the URL, the presenter window's slide list, the phone remote's and agents' slide list, and the PDF, HTML and PNG exports. **Exports hold the chosen sections only**: what you present is what you print, and a handout of 6 of 20 sections is the reason to choose. Choose every section to export everything. Document mode, the editor, the comments panel and the document title keep the whole file: the reading view is the file (rule 1), and an author edits all of it. **A link to a skipped section.** `#<skipped-id>/<n>`, and a GitHub anchor of a heading inside a skipped section, open on the first chosen slide, and the hash is rewritten to that slide's address. The selection wins over the address because `?sections=` is the sharer's explicit choice and the hash only says where to start. An id the document does not have behaves as before (first slide). There is no notice: the same rule already covers an unknown address. **Followers and the presenter window.** The room messages do not change. A follower ignores `?sections=` and builds the whole document (the presenter's current address always exists in it), so its counter counts every slide, not the chosen ones. The follow link does not carry the selection; carrying it would need a change to the room's `state` message or to the link, which belong to decisions 68 and 73. The share link (decision 7) builds its query from the document's source alone, so it leaves out `?sections=` as it leaves out `?level=`, and the owner decides whether it should carry the choice. The presenter window lists the addresses it is sent, which are the chosen ones; it still builds previews for the skipped sections, which costs time but shows nothing. **Interface.** The sidebar shows "Sections: all" or "Sections: 4 of 12" on a button under the level select. On a screen 640 px wide or less the sidebar leaves that button out: there the sidebar shares 40 to 50 % of the height with the file tree, and the button pushed the outline below three rows (`e2e/workspace.spec.ts`), so More actions and the palette open the dialog. It opens a modal dialog with one checkbox per section in document order (title; a part after a thematic break reads "title · continued"), "Select all", "Clear" and a "Show N sections" button that applies the draft. Apply is disabled while no box is checked, and the dialog says so in a description tied to the button. Checking every box applies as no selection. The same dialog opens from the command palette and from More actions (the sidebar is absent in document mode on a phone). The checkboxes are React Aria's `CheckboxGroup`: Tab moves between boxes and Space toggles one, each box has a visible label, and a status line under the boxes announces how many are checked. Rejected: checkboxes inside the outline (an option in a listbox cannot hold a control), applying each click at once (Clear would show every section while every box is empty), a `<!-- skip -->` comment in the Markdown (the file would carry viewer state, rule 1), and positions in the URL (rule 7). | accepted                |

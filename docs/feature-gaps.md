# Feature gaps

A survey of what other Markdown and slide tools offer that docwalk does not,
checked on 2026-11-06 against `main` plus the code-highlighting branch
(decision 76). It complements [`prior-art.md`](./prior-art.md), which chose
the architecture. Candidates that docwalk takes on move to
[`ROADMAP.md`](../ROADMAP.md) and get a decision row before code.

## How this list was made

1. Start from the tools [`prior-art.md`](./prior-art.md) already covered,
   and add 2025–2026 tools found by search (presenterm, margo, md2slides
   and AI deck makers).
2. Read each tool's feature docs, README or source. A feature counts only
   when a page or a line of code shows it; the rest is marked unverified
   at the end of this file.
3. Check docwalk's own source for each feature before calling it a gap, so
   nothing it already has is listed (the next section).
4. Rate each gap for docwalk's audience (a team walking through a design
   document), estimate the effort, and test it against the project rules
   in [`AGENTS.md`](../AGENTS.md), above all rule 1: syntax GitHub does not
   render is rejected unless it degrades to clean text.

## Already in docwalk (confirmed in source)

Reveal.js progress bar (`progress: true`), blackout/pause (B, `.`), arrows; elapsed timer and clock in
the presenter window; QR codes for remote and follow links; phone laser to the presenter screen;
pen, laser, arrow, eraser with per-slide undo; command palette that jumps by **slide title**;
idle-hiding chrome (decision 75); Shiki colours (colour only, no line highlighting).

Confirmed **absent**: speaker notes of any kind; math; emoji shortcodes; transitions (`transition: "none"`);
annotation persistence (nothing in `src/annotate` touches storage); strokes, laser or diagram focus on
followers or the presenter window (`RemoteMessage` carries only slide state, and `laser` goes remote ->
presenter); focus view for anything but Mermaid; Wake Lock; full-text search (palette filters titles only).

### Rejected by rule 1 (custom syntax that does not degrade on GitHub)

- Slidev `v-click`, `<v-clicks>`, `v-mark`, layouts, `<Toc>`, ` ````md magic-move ` wrapper, Comark `::code-group`: components or wrappers show as raw text or code on GitHub.
- Quarto/Pandoc fenced divs (`::: notes`, `::: {.incremental}`, `:::: {.columns}`, `. . .`): visible as text on GitHub.
- reveal.js / HedgeDoc `Note:` paragraphs and `<!-- .slide: data-… -->` (the comment degrades, but per-slide backgrounds are presentation state that rule 1 puts in the viewer).
- deckrun `{reveal}` suffix: shows as literal text on GitHub.
- Obsidian wiki links and `![[embeds]]`; MPE `<!-- slide -->` separators (degrade, but docwalk splits on structure, so they add nothing).

These degrade gracefully and are acceptable if wanted: HTML comments (notes, `<!-- pause -->`, `<!-- skip -->`), Marpit's
fragmented lists (`*` bullets and `1)` numbering render exactly like other lists on GitHub,
[fragmented-list.md](https://github.com/marp-team/marpit/blob/main/docs/fragmented-list.md)), and info-string meta (unverified, see above).
Step-through list reveals can also be a pure viewer toggle with no syntax.

## 2. Top 10 recommendations, ranked

1. **Speaker notes from HTML comments.** Every serious tool has notes and docwalk has none. Comments are the one notes syntax GitHub officially hides, so the doc stays clean; it also unlocks notes export and PPTX notes.
2. **Focus view for code, images and wide tables.** It reuses the diagram-focus machinery and turns rule 3's "too tall" note into something the presenter can show. Add interactive line spotlight while there.
3. **Mirror laser, strokes and diagram focus to followers and the presenter window.** Follow links are docwalk's remote-meeting story, and today followers cannot see what is pointed at. The E2E and signature design (decisions 68, 73) already fits it.
4. **Pick sections to present (viewer-side skip list in the URL).** Long design docs rarely get presented whole; this fits rule 1 exactly and costs little.
5. **Persist annotations and export them.** A review's marks are its outcome. Store them like comments and include them in PDF/PNG.
6. **Countdown, pacing bar and Wake Lock.** Three small presenter-window fixes that every time-boxed review needs.
7. **Math and emoji shortcodes.** Both are GitHub-native, so leaving them out is a fidelity gap under docwalk's own promise. Math follows decision 76's after-sanitizer pattern.
8. **Diagram tour (step through Mermaid nodes and paths).** No tool has it, and it builds on docwalk's strongest feature: node ids, focus and comments already exist.
9. **Full-text search in the palette.** Cheap, and it answers the most common mid-meeting question: where did the doc say that?
10. **Blank whiteboard plus shapes and stylus auto-detect.** Reviews end up sketching an alternative. drauu already supports rectangles, ellipses and lines.

Next tier: image PPTX export; structure-derived two-column layout; line highlighting from the info string (after a GitHub check);
local walkthrough recording; CI overflow check; richer MCP tools.

## 3. Where docwalk is already ahead of all of them

- **Honest overflow plus semantic pagination** after real render (fonts, Mermaid, images): only md2slides measures and splits, and it is a CLI. Everyone else clips, scrolls or shrinks.
- **Unmodified GitHub Markdown in**, with Pandoc's slide-level rule, GitHub anchors, alerts and per-slide footnotes. Slidev, deckrun, HedgeDoc and Marp need `---` or directives; Quarto needs a compile.
- **Full Mermaid in strict mode** with zoom, pan, pen inside the diagram transform, node-level comments and Excalidraw conversion. Marp v5 covers 6 diagram types; deckrun runs Mermaid `loose` with no sanitizer.
- **End-to-end encrypted remote and follow** with signed state. Slidev `--remote` exposes the dev server; md2slides broadcasts over LAN SSE with no access control; Quarto multiplex uses a hosted server.
- **Browser-only static app, offline PWA, no install, no account.** Slidev's PWA is opt-in on a Node build; Marp, presenterm and margo are CLIs or desktop apps.
- **Hostile-input posture** (double sanitizer, Mermaid pre-pass, image gate, CSP). Slidekick uses a denylist sanitizer.
- **Agent edits with E2E and presenter consent.** Slidev's MCP is an unauthenticated local HTTP endpoint on the dev server.
- Section-addressed links that survive edits, a local-folder workspace with live reload, and an en/tr UI.
